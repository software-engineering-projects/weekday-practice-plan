# Weekday Practice Plan (2 hours/day)

## Core Goal

Build speed and clarity in:
*   problem solving
*   writing correct logic
*   understanding data structures
*   debugging code

## Topics to Practice (in order of importance)

### 1. Arrays and Strings (FOUNDATION)

**Focus on:**
*   iteration patterns
*   searching
*   sorting basics
*   prefix sums
*   frequency counting (hash maps)

**Why:**
Most backend logic is built on these patterns.

### 2. Hash Maps / Dictionaries (VERY IMPORTANT)

**Focus on:**
*   counting problems
*   lookup optimization
*   grouping data
*   caching logic patterns

**Why:**
This is heavily used in backend systems (fast lookups, validations).

### 3. Two Pointers

**Focus on:**
*   pair problems
*   sorted arrays
*   optimization of loops

**Why:**
Common in filtering and validation logic.

### 4. Sliding Window

**Focus on:**
*   subarray problems
*   rolling calculations
*   real-time window logic

**Why:**
Very similar to logs, events, and streaming data logic.

### 5. Stack

**Focus on:**
*   undo operations
*   parsing logic
*   expression evaluation
*   validation problems

**Why:**
Used in workflow systems and parsing business rules.

### 6. Queue / Deque

**Focus on:**
*   task scheduling
*   BFS basics
*   processing pipelines

**Why:**
Very close to backend job queues and workflows.

### 7. Trees (Basic only)

**Focus on:**
*   traversal (DFS, BFS)
*   hierarchy structures

**Why:**
Used in organizational data, nested systems.

### 8. Graphs (Light introduction only)

**Focus on:**
*   BFS / DFS
*   simple dependency graphs

**Why:**
Useful for workflows and system dependencies.

### 9. Recursion (supporting topic)

**Focus on:**
*   base case thinking
*   breaking problems into steps

**Why:**
Helps in structured logic building.

## Weekly Structure (Simple)

### Monday–Friday (2 hours/day)
*   30 mins: learn concept
*   90 mins: solve 2–3 problems
*   focus on understanding patterns, not speed

### Saturday or Sunday (Projects day)
*   apply what you learned in real backend systems
*   build features like:
    *   APIs
    *   workflows
    *   database logic
    *   state changes

## Problem Solving Style (IMPORTANT)

For each problem, train yourself to always think:
*   what is the input?
*   what is the output?
*   what state changes happen?
*   what rules apply?
*   how do I store data efficiently?

This directly matches backend engineering thinking.

## What to Avoid
*   competitive programming speed pressure
*   overly complex math puzzles
*   random LeetCode grinding without patterns
*   focusing only on “hard” problems early

## Outcome After 2–3 Months

You should be able to:
*   write clean backend-style logic in Python
*   understand common coding patterns
*   debug your own code faster
*   implement APIs and business logic more easily on weekends
